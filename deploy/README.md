# Deploying Rift

```
deploy/
  helm/rift/        application chart: services, workers, gateway, web, policies
  terraform/
    modules/platform    ingress-nginx, cert-manager, NATS, LiveKit, Argo CD, monitoring
    modules/datastores  Postgres, Redis, MinIO on cluster storage (swap for managed services)
    modules/rift        namespace, secrets and the Rift release (Helm or Argo CD)
    envs/local          kind cluster with Calico; everything above on a laptop
    envs/cloud          the slot for a managed cluster
  argocd/envs/        per-environment values that CI bumps on release
  scripts/smoke.sh    end-to-end check through the ingress
  Makefile
```

## Local cluster

Requirements: Docker, `kind`, `kubectl`, `helm`, `terraform`. The subnet of kind's docker network is read from `docker network inspect kind` after the cluster is created (override it with `node_cidr`), because LiveKit posts webhooks from the node address (Calico rewrites it to the node's VXLAN tunnel address inside the pod subnet, which is why the pod subnet is allowed as well). Ports 80 and 443 on the host must be free; LiveKit needs one TCP and 21 UDP ports (defaults 7881 and 7882–7902; set `livekit_tcp_port`/`livekit_udp_port` in `envs/local/terraform.tfvars` when docker compose already uses them).

```sh
make -C deploy local-up
```

Set `monitoring = true` in `terraform.tfvars` to add kube-prometheus-stack (Grafana at `https://grafana.localtest.me`; the admin password is generated, read it with `kubectl -n monitoring get secret grafana-admin -o jsonpath='{.data.admin-password}' | base64 -d`); the Prometheus Operator CRDs are installed before the other releases so their ServiceMonitors can be created. The app chart then also ships a PodMonitor for `outbox-worker` (`rift_outbox_pending_events`, `rift_outbox_stuck_events`, `rift_outbox_oldest_pending_age_seconds` on `/metrics` of its health port) and alerts on events that keep failing to publish. That builds every image as `rift/<service>:local`, creates the kind cluster, installs Calico, ingress-nginx, cert-manager, NATS, LiveKit, Postgres, Redis and MinIO, deploys the chart and runs the smoke test. The app is at `https://rift.localtest.me`. Certificates come from a local CA that Terraform generates into `envs/local/rift-local-ca.crt`; trust it once with `make -C deploy trust-ca` (macOS Keychain) — accepting a self-signed certificate in the browser is not enough, Safari does not extend that exception to WebSockets, so LiveKit and the realtime socket would silently fail. `make -C deploy local-down` destroys the cluster.

`local-up` builds the images first (`make -C deploy images`), which takes a while on the first run because the Rust services compile from scratch. Reusing images already built by docker compose: `docker tag rift-identity-service:latest rift/identity-service:local` for each service, then `make -C deploy kind-load` and `terraform apply` in `envs/local`.

To pull released images from GHCR instead: `image_registry = "ghcr.io/rift-space/rift"`, `image_tag = "1.2.3"`, `ghcr_user`/`ghcr_token` with `read:packages`.

## Delivery modes

In Argo CD mode the image registry and tag come from `argocd/envs/<env>/values.yaml`, not from Terraform's `image` input. `modules/rift` either installs the chart itself (`delivery = "helm"`, the default for local) or creates an Argo CD `Application` (`delivery = "argocd"`) that syncs `deploy/helm/rift` from git with `deploy/argocd/envs/<env>/values.yaml` on top. Terraform still owns the namespace and the secrets in both modes; the chart only references them through `existingSecret`. See `argocd/README.md` for how CI moves the image tag.

## CI/CD

- `Infra` (`.github/workflows/infra.yml`): on pull requests touching `deploy/` — `helm lint`, `helm template`, `terraform fmt/validate`, web image build. Weekly and on demand (`cluster: true`) it brings the local environment up on a runner with the `latest` GHCR images and runs `scripts/smoke.sh`.
- `Release Services`: builds `ghcr.io/rift-space/rift/<service>` for every service and `web`; on a `vX.Y.Z` tag it then commits `image.tag: X.Y.Z` into `argocd/envs/staging/values.yaml` so Argo CD rolls the release out.
- `Release Web`: on the same tag builds the static web bundle and attaches `rift-web-X.Y.Z.tar.gz` to the release in `rift-space/rift-releases`, next to the desktop binaries electron-builder publishes there.
- `Release Desktop`: unchanged, publishes macOS/Windows/Linux builds to `rift-space/rift-releases`.

## Datastore and bus access

Postgres, Redis and MinIO carry passwords generated by Terraform, and NATS requires a generated user; the credentialed `NATS_URL` and `REDIS_URL` live in the release Secret, never in the ConfigMap. NetworkPolicies in `rift-data` and `nats` admit only the namespaces listed in `datastores.clients.namespaces` and `nats.client_namespaces`. Redis additionally admits `datastores.clients.redis_cidrs` for the host-networked LiveKit pod; on kind that list has to include the pod subnet because Calico's VXLAN mode sends host traffic from the node's tunnel address, so locally the Redis policy only keeps out traffic from outside the cluster and the password does the rest. On a cloud cluster list only the LiveKit node CIDR.

## Overriding chart values

Every Helm release the modules install takes a `values` input that is laid over the generated values by `modules/deepmerge`: maps are merged key by key down to four levels, lists and scalars replace what the module generated. Adding `controller.config["log-format-upstream"]` to ingress-nginx or `grafana.adminPassword` to monitoring therefore keeps the generated timeouts, ingress hosts and TLS settings.

## Secrets hygiene

`*.tfvars`, `*.tfstate*`, `.terraform/` and the generated CA certificate are ignored by git. The `Secrets` workflow scans every pull request with gitleaks and fails when such files are tracked.

## When a cloud provider appears

Only `envs/cloud` changes: a `cluster.tf` for the managed Kubernetes, a datastores module with the same outputs backed by managed PostgreSQL/Redis/object storage, DNS records and a remote state backend. `modules/platform` and `modules/rift` are reused as they are; switch `cert_manager.issuer` to `letsencrypt` and `delivery` to `argocd`.
